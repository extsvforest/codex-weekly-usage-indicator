# Agent guide

This repository contains a small Windows WinForms utility with optional WSL Codex integration. Keep changes focused and dependency-free unless a new dependency is clearly necessary.

## Architecture

- `UsageIndicatorForm` owns widget lifecycle, drawing, polling and interaction. `AccountManagerForm` contains the Codex and Claude account surfaces.
- `CodexDesktopStateReader` detects the packaged Codex Desktop host. `AppServerClient` runs the local official `codex app-server --stdio` and speaks JSONL. Codex weekly usage is the returned window closest to seven days.
- `CodexAccountStore` owns the encrypted Windows login vault and recovery; isolated account queries are separate from active widget polling and the manager's combined observation set.
- `ClaudeAccountController` binds verified profile identity and widget usage. `ClaudeProfileStore` holds non-secret metadata; `ClaudeProfileRuntime` invokes the unmodified official CLI for sign-in, identity checks and usage only.
- `ClaudeShelfService` (owned by the widget) observes the packaged Claude Desktop app off the UI thread. `ClaudeDesktopProbe` reports run state, the installed package and the compatibility guard; `ClaudeDesktopLogWatcher` follows the app's own log for the current run's account. `ClaudeSessionShelf` fills other accounts' Code session lists ("shelves"); `ClaudeShelfAccounts` maps profiles to account/organization pairs; `ClaudeAppFollower` keeps the widget's usage selection on the app's confirmed account.
- `ClaudeCodeUsageSource` parses official `/usage` output. `ClaudeUsageClient` owns the shared request throttle, caching and backoff; `ClaudeDisplayMetric` selects overall or Fable weekly without issuing a query.
- `WslCodexBridge` probes and operates supported Linux targets. `WslCodexService` owns per-target encrypted login bindings and journals; `WslCodexSwitchCoordinator` handles linked Windows/WSL progress, recovery and explicit abandonment.

## Authentication and data invariants

- Never read, print, log, copy, persist or transmit Claude authentication tokens. Official Claude Code owns sign-in, sign-out and refresh. Do not add a Claude token vault, OAuth implementation, proxy or global CLI shim.
- Preserve the original Claude home and its default global-config behavior. Additional profiles have separate official authentication; existing skills, projects and other working data stay in place. Never share the whole home or blindly copy account configuration. Preserve existing files if a link or registry is unsupported.
- The Claude Desktop account changes only through the official app (sign out and sign in). The utility never swaps logins, has no manual Claude "switch", and never starts an interactive Claude session with a utility profile; such a writer would be invisible to the app's own "in use" check.
- **In use** means the account the running Desktop app has confirmed in its current run: an initialization of a registered account/organization pair logged after the app's host process started. Sign-out, an unregistered account, a new app run or any gap in following the log invalidates it; a closed or uninspectable app has no current account. Identify the followed log file by its volume and file index from the reading handle, not its creation time (a new `main.log` inherits the renamed file's creation time on NTFS); an unreadable file, a rotation that cannot be bridged or a rotated file ending mid-line is a gap, and no account is confirmed from lines before a mid-line end. The widget follows the confirmed account by selecting its verified usage profile on the UI thread, and a selection that outlives its reason is discarded. A failed selection is retried after two minutes, or at once after that account's usage check or sign-in succeeds; a newer app account replaces a selection in flight, and only the current request may change the follow state. While the running app is signed out, on an unregistered or not yet confirmed account, or on an account other than the selected usage profile, show `—` with the reason, never another account's number. A lapse in observing the same run, or an app process that cannot be inspected, keeps what was shown; a closed app, or a new run not observed yet, shows the last selection. Shared settings and safe-mode usage must resolve to the same subscription identity. Never return an old profile/account observation under a new selection.
- Session lists: Desktop reads only `%APPDATA%\Claude\claude-code-sessions\<account>\<org>\local_*.json`; transcripts under the Claude home's `projects` are shared by every account. Fill other accounts' lists **add-only**, and only while Desktop and its Code CLIs are fully closed. An unknown process state is not closed. Re-plan immediately before publishing, check Desktop again before every file, and hold the lease that lifecycle scripts take. Never modify or delete a record the app wrote.
- A new record gets a fresh `local_<uuid>` app id and the source's current `cliSessionId`. It carries the display fields, a validated model and explicit effort, and the lineage ids (`priorCliSessionIds`, `rewindEdges`, `transcriptCuts`); the app protects transcripts from deletion per id. `adoptedFromOtherSurface` follows the source. Permissions, approvals, connectors, bridge/remote-control state, trust anchors and fork/spawn links are never copied.
- Skip archived sessions, sessions without a current transcript id, folderless scratch sessions (the app deletes their folder without checking other accounts), remote, worktree and Cowork sessions, missing folders or transcripts, and sessions a live CLI is writing. Only `<pid>.json` files in the `sessions` registries of the Claude home and every utility profile are registrations; one is a writer while that process lives with a matching start time. A malformed registration of a live process, or a registry that cannot be read, holds every list; one of an exited process is ignored whatever its age. Hold a target list that has `.json.tmp` recovery files or unreadable records. Treat a `deleted_` marker or a ledger record the user removed as that account's decision, and never recreate it.
- Judge presence by conversation lineage: an id listed in any record's `priorCliSessionIds` is an older state of a conversation that list already has. Never copy an older state. A copy this utility made whose current id a newer record (existing or being published) in the same list now lists as earlier is archived in place (`isArchived`), never deleted, and only while the app has not continued that copy. Records the app wrote are never archived or changed.
- A copy follows its original's title (`title`, `titleSource`) while it is still that original's copy: the same `cliSessionId`, not archived, not used in its own account after the original (`lastActivityAt`), and not renamed there since its title was last in step (the ledger's `title`). An older entry without a recorded title starts tracking once the copy shows the original's title; until then only a copy byte-identical to what was written is renamed. The app's `previousTitles` cannot prove a copy kept its name: it records neither a first name nor a change of case or spacing. The holds that apply to filling apply here (lists outside the run, held lists, live writers). Write only while Desktop is closed, through a partial file, and only if the copy still holds the bytes the decision read; a failed write leaves the run unfinished. The ledger hash follows the new bytes only when the copy was untouched.
- Pins and groups are not carried across accounts. Desktop keeps them in web-UI state it owns: the settings file's `preferences.epitaxyPrefs` and the localStorage `LSS-persisted.*` keys are mirrors it rewrites on start; the zustand `dframe-store` in localStorage holds `pinnedOrder` and `customGroupsByScope`, but the app reconciles other accounts' groups on start; the Code list's starred pins persist in IndexedDB (`dframe-starred-code`). Live tests in October 2026 lost every write to the settings file and to localStorage. Chromium retries its LevelDB lock for about a second and may then destroy the database, so never write web storage while the app could start. Production passes no settings path; `ClaudeSidebarPrefs` and `ClaudeLocalStorage` remain for read-only diagnosis and tests. Do not re-enable without a source of truth the app keeps and a write the app's start cannot race. (Corrected 2026-10-12: the Code sidebar shows the IndexedDB list `store:pin-state:dframe-starred-code`, one list for every account; the user confirmed on screen that a session whose record says `isStarred: true` was not pinned. Records are a mirror: the app pushes the list into them on start, `true` only, and never clears a stale pin, and the session tools' `pinned` reports the record. The 10/07 check had compared two record-backed sources.)
- Session layout reference: `session-reference.json` in the shelf ledger folder (account/org, label, labels of mapped accounts) names it, and only the widget writes it. The account page sets or clears it on request. The widget also moves it on a switch: when the app's confirmed account changes from K to J within the widget's lifetime, K becomes the reference if it already is one, if there is none, or if the plan command signalled K aligned with the reference still in place after the app arrived at K; otherwise it stays, because K may hold a stale layout. Lost log lines, or more than one sign-in since the account was last confirmed, drop the confirmed account and the alignments learned before them: the app may have left an account and come back. The log watcher counts sign-ins (login-state transitions to an account; an app start logs none) over every line it reads, across passes and app runs: when it replays a new run it also reads the lines written since its last read, up to where the replay stopped (the rest of `main.log`, or of the rotated file and the new one), and reports lines it cannot find as lost. The plan command signals by setting the widget's named event `Local\CodexWeeklyUsageIndicator.SessionsAligned.<account>_<org>.<reference account>_<org>.<reference setAt UTC ticks>` (auto-reset) when its plan for the current account against the stored reference (no `--reference` override) leaves nothing to create, move, pin or rename and has no warning about pins, groups or the ledger. The widget creates the events only for the reference in place and drops the others, so a plan measured against an earlier reference is never heard. A switch to an account that lacks sessions arms the reopen once, unless one is armed, the version is unreviewed, or the user made a reopen choice while that pass ran. The skill runs only when the user invokes `/claude-session-sync` (`disable-model-invocation`). `WeeklyUsageIndicator.exe --claude-session-plan --session <local id> [--reference <account/org>]` runs before the single-instance claim and prints a read-only plan as UTF-8 JSON: titles from each account's session records, pins from the IndexedDB pin list (`ClaudeSidebarPins`; records' `isStarred` is never read), groups from `dframe-store` `state.customGroupsByScope`, both read with full sharing while the app runs. Unreadable pins plan neither pins nor group moves (a move unpins); a reference without a single pin while this account has some is treated as a wiped list and leaves pins alone. Conversations match by current transcript id, else as a continuation either way. A record the widget copied into the reference's list (its ledger) shows the conversation as copied, not a choice made there: it gives a pin only when pinned there, a group only when filed there, and a title only once renamed there (`previousTitles`, which copies never carry); each part it does not give, this account keeps from its own, an older state's pin and group included. A ledger that is there but cannot be opened or read whole (`ledger_unreadable`) plans no pins, groups or titles; only a missing ledger means no copies. A group assignment the scope does not list moves nothing and is reported (`groups_unresolved`). An older state is a record whose current transcript another record of the same list lists as earlier (not mutually, the lister no fork or spawn) and that has no entry after the conversation went on. It went on in the transcript every continuing record lists right after this one, which must also be the first created after it, at that transcript's oldest entry whose `uuid` this one does not hold: a continuation starts with copies of the earlier entries, ids and times kept (reviewed 2026-10-12 on nine real hand-overs: that entry is within half a second of the file's creation). The file must have been created by then (2 s slack), or it was restored and proves nothing. One written to afterwards is a branch and stays, as does the calling session. Every transcript of the record, of the continuing lineage and of the newest state must be present and dated, or the record stays; a file created after it was last written was copied. Only each line's top-level `uuid` and `timestamp` count. Record `createdAt` is per conversation and `lastActivityAt` moves without messages, so neither dates anything. This account's older states are listed for archiving; the reference's are seen through, their pin and group passing to the newest state, and a conversation the reference does not list hands its own older state's pin and group on. An older state is `ready` only when pins and both groups are readable, the reference pin list is not empty, the groups of the older state, of the target and of the newest state all resolve, and the newest state already holds the pin and group it should, so stopping part way never loses a pin or group. In the reference account the plan (`is_reference`) only clears older states. It also lists both sidebars by title (pinned sessions only under Pinned) and the conversations only one side has; `--settle <seconds>` waits before reading so a check after applying sees the app's writes. The Claude-only `claude-session-sync` skill applies it with the app's own session tools in a fixed order (create groups, move, pin — a move into a group unpins — then rename), re-plans to confirm, then archives ready older states with the app's archive tool (unpinning just before) only after the user agrees, and shows both sidebars side by side. Nothing is deleted, other sessions or groups only one side has are left alone, and the widget never writes the sidebar. Only the widget writes the reference: a process inside the Claude app (MSIX) that wrote the ledger folder would create a virtualized copy that hides the widget's file from the plan command.
- The fill ledger (`%LOCALAPPDATA%\CodexWeeklyUsageIndicator.SessionShelf`) records intent before publishing and keeps only files whose content matches. Creation history is retained indefinitely; runs are capped. Undo removes only records the app never changed.
- Reopen Desktop only when the user asked on the account page. The first fill pass of the next closure consumes the request whether or not the reopen succeeds; a cancelled or replaced request is never used, an app that is already running again is not launched, and a request expires after 30 minutes, including while a pass runs.
- Map a profile to its account/organization only from the non-secret `oauthAccount` fields of the official global config, and only when they hash to the stored identity. Conflicting sections stay unresolved. Cache the mapping by profile, identity and config path. Removed profiles leave the cache.
- Before writing, the installed package must contain every compatibility marker, connected window and data flow (`ClaudeDesktopProbe`); otherwise pause writes and say so. The flows check, allowing renamed minified variables, that each record's current and earlier transcript ids enter the claims set, that a session delete releases only unclaimed ids and asks the reap decision, which refuses claimed ids and fails closed on unreadable records, and that transcripts are removed only when that decision allows it, with nothing reassigning it and a failed check only logging and keeping. What a guard's keep call returns is not checked. This guards against drift, not against every change of meaning. Re-verify the design when a check fails. While the app runs, an unreviewed version is reported at once (footer and tray), so nothing promises a fill that will not run. Reviewed 2026-10-08: 2.26454 spreads earlier ids, plus remote earlier ids for mirrors, into one loop that adds them all to the claims set; under `localOnly` current ids also pass a UUID check (`isUuid`), which local CLI ids do.
- Processes started inside a packaged app (for example an agent shell) may have new `%LOCALAPPDATA%` files redirected to that app's private LocalCache. Run lifecycle scripts and live checks from an ordinary Windows session.
- Codex login replacement requires explicit user selection and stopped writers. Keep current live credentials authoritative during recovery; do not overwrite newer or different authentication with an old snapshot.
- Discover only running WSL distributions on an explicit environment check. Require an installed native Linux CLI, identified Linux user/home and supported file-based auth. Never force-install a missing CLI or rewrite unsupported managed/keyring settings.
- Save independent WSL logins for each bound account and require a binding for the live source before switching. Isolated login preparation may run while jobs continue; live capture/replacement must reject running or unidentifiable writers. Do not kill user jobs.
- Keep WSL credentials out of arguments, environment variables and diagnostics. Use private pipes, restricted Linux files, encrypted Windows vaults, conditional replacement and actual account verification. Windows/WSL cannot commit atomically; retain durable per-target and coordinator journals across partial failure.
- Explicitly abandoning a WSL link must archive encrypted recovery records and disable linked switching without writing either environment's authentication. Uninstall preserves the separate Codex vault, WSL journals and Claude profile directories. Removing a Claude list entry must not delete its files.

## Usage and presentation invariants

- Do not add telemetry or direct provider usage network calls. Do not commit absolute local paths, real-account screenshots, pet assets, build output or credentials.
- Treat `account/rateLimits/read` and Claude Code `/usage` text as changeable contracts; fail gracefully without substituting a different limit.
- Run Claude usage in safe mode without a shell, browser integration or session persistence and with `--max-turns 0`. Require `num_turns == 0` and `total_cost_usd == 0`. Official last-known output must not become a fresh observation.
- Actual Claude usage calls must remain at least ten minutes apart per verified account, including manual refreshes, failures and cancellations. Different accounts have independent intervals; profiles with the same verified identity share request spacing and transient backoff. Metric selection reuses the snapshot. A new install defaults to overall weekly; existing settings without a metric preserve Fable.
- The manager's Claude tab checks every verified account once when first shown and on Refresh, the selected one first and one at a time, skipping accounts that need a sign-in. It goes through the same per-account interval, so a recent observation is reused; other accounts are never polled in the background. Its total counts each verified identity once at 100%, only from a fresh, usable overall-weekly observation; a stale value, failure, missing sign-in or expired window withholds it. The Fable window is never added in.
- Keep the enabled Claude half visible when data is missing or fails. The selected window alone drives its number; show `—` when absent or expired. Parse and expire five-hour, overall-weekly and Fable-weekly windows independently. Share rounding across widget, tooltip and copy text.
- Persist at most one credential-free Claude recovery snapshot containing percentages, resets, check time and an opaque profile/account key. Reject another identity's cache; use matching data only after a transient live failure, expire it after 24 hours or when all windows expire, and clear it on authentication/schema failure. A saved snapshot must not suppress the first live request in a new process. Cached in-memory observations obey the same identity and expiry boundaries.
- Opening a new manager performs one sequential Codex batch; only explicit full refresh starts another. Active polling and individual reads do not silently certify a new aggregate. Missing, expired, failed or canceled rows withhold the full total.
- Preserve Korean/English coverage, the approved light paper design, stable first paint and tooltip hover, keyboard navigation and three-account fit. A synthetic HTML reference alone does not prove the native UI; inspect native captures at supported DPI settings.
- Stop the widget's Codex app-server child when the widget pauses or exits. Preserve singleton behavior and topmost tool-window presentation without keyboard focus or foreground changes. Do not restore topmost through an activating WinForms `TopMost` assignment.

## Install lifecycle

- Launch `--supervise` through the per-user interactive, least-privilege scheduled task, never directly from Codex. The supervisor retries abnormal exits/start failures only; normal Close ends supervision. Do not replace this loop with Task Scheduler RestartOnFailure.
- Disable/stop the task before upgrade or uninstall; filter processes by the current user's exact installed EXE path. Coordinate lifecycle scripts with in-progress account operations.
- Check the install directory's final handle path before stopping tasks or processes: packaged shells can redirect AppData without reporting package identity. Package `install-environment.ps1` with both lifecycle scripts.

```powershell
.\scripts\build.ps1
```

Keep regression coverage for:

1. Settings migration, metric selection without a query, independent window expiry, consistent rounding, per-account request spacing across duplicate profiles and profile-bound recovery values.
2. Claude official process arguments, identity checks, shared-data preservation and default-home semantics. Fixture tests do not establish a successful real second-account login.
3. Claude session lists: add-only planning and exclusions, closed-app and per-file Desktop checks, writers appearing before publishing, registry naming and liveness, pending-intent recovery, undo, account mapping, log generations, gaps and rotation, compatibility-guard mutations, the widget's usage gate, reopen requests (consume, cancel, replace, expire) and the account page's In use badge and reopen action. Fixture tests do not establish a real account round trip; record that separately.
4. WSL missing/unsupported environments, busy writers, independent login binding, partial failure, restart-safe recovery, identity mismatch and authentication-write-free abandonment.
5. Native account/tooltip UI at supported scales and both languages: stable first paint, preserved focus, selectable controls and no clipped primary actions. Preserve the existing `AccountUiSmoke` focus/topmost and hover regressions.
6. Installer/supervisor ownership: one supervisor and one widget; abnormal widget exit recovers after about a minute; normal Close ends both; uninstall removes the task before the app and preserves separate account/profile data.
7. Release artifact inspection: no username or absolute user-profile build paths, credentials or real-account screenshots. Report actual validation boundaries; do not describe synthetic tests as completed live account switching.
